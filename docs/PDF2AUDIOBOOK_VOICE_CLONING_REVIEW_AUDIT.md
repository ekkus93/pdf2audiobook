## Code quality and evidence limits

Typed built-in/reference selections feed the existing synthesis and repair pipeline.
Canonical immutable snapshots and hash-only identities avoid pathname-based reuse.
Private worker pipes, descriptor-level print suppression, locked temporary directories
(and Rust child-lifetime hooks) have exercised privacy and cleanup paths. New tests
cover precedence, malformed media, output bounds, narration transforms, progress/cache
identity propagation, clone repair parity and clone-populated event logging.

The adapter depends on pinned SDK internals (`_speaker` and artifact-loader redirection),
so SDK changes require renewed compatibility evidence. Worker support is POSIX-only.
The unresolved resume case shows that dependency availability and saved identity still
interact at a boundary not covered by the original tests. Offline fake providers prove
control flow and isolation; they do not prove speaker similarity or accelerator behavior.
Structured CLI error objects are a trusted protocol; real Python errors are tested for
content-free output, while Rust tests cover raw unstructured stderr and event redaction.

Current gate counters and skip reasons are in the [authoritative validation table](PDF2AUDIOBOOK_VOICE_CLONING_TODO.md#current-validation-state).
